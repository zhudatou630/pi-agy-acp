# Pi Web × Antigravity ACP：源码调研

**范围**：只读检查 pi-web 源码（`be5b72c9f`，Pi Web 1.8.3）和全局安装的 Pi Web 1.8.3 / Pi SDK、pi-ai、pi-agent-core 1.6.0。起点：`AGENTS.md:40–81`、`CONTEXT.md:1–17`、`README.md:11–45`、`docs/extensions.md`、`docs/ui.md`、`docs/chat-tabs.md`、`docs/adr/0002-chat-only-tool-selection.md`。未启动服务或运行 ACP；以下是源码行为，不是浏览器实测。

**引用约定**：无前缀的 `file:line` 相对于 pi-web 源码仓库根目录。`SDK/`、`AI/`、`CORE/` 分别相对于pi-web 全局安装目录下 `node_modules/@earendil-works/` 里的 `pi-coding-agent/`、`pi-ai/`、`pi-agent-core/`。版本见 `package.json:3,50–53`、`SDK/package.json:3`、`AI/package.json:3`、`CORE/package.json:3`。

**结论**：ACP 的思考、正文、权限对话框可以直接复用现有能力。**ACP 已执行的工具绝不能作为正常完成的 Pi `toolCall` block 直接返回**：该 block 是执行请求，不是展示记录。首版建议用标准 `thinking` / `text` 流、`ctx.ui.confirm` / `select`，再用 Markdown 或收尾时的可见 custom message 显示计划、工具摘要、终端输出和 diff。要原生步骤卡、增量状态与 diff，优先给 Web 加一个只展示、不执行、与模型上下文隔离的 ACP 数据契约。依据：`CORE/dist/agent-loop.js:147–194,478–526`、`components/MessageView.tsx:1177–1208,2106–2197`、`lib/rpc-manager.ts:2017–2109`。

## 1. 传输与消息渲染

### Browser → Web server → SDK（同进程）

- 浏览器 POST JSON 到 `/api/agent/[id]`（新会话 `/api/agent/new`）；服务端 wrapper 的 `send()` 把命令转成 SDK 调用。`startRpcSession` 是历史命名：并没有启动 `pi --mode rpc` 子进程。用 `createAgentSessionServices()`、`createAgentSessionFromServices()`、`SessionManager.open/create()`，绑定扩展 UI 时标记 `mode: "rpc"`，调用 `inner.prompt()` 等。`lib/agent-client.ts:38–65`；`app/api/agent/new/route.ts:19–28,49–91`；`app/api/agent/[id]/route.ts:76–104`；`lib/rpc-manager.ts:737–763,1194–1213,2932–2939,3018–3050,3108–3119`。
- 反向通道为 `/api/agent/[id]/events` SSE：`AgentSession.subscribe()` → wrapper `onEvent(..., true)` → EventSource。Web 投影裁掉 system message、部分 provider signature 及累积的 `partial`，以索引和 delta 发流；重新连接可同步当前快照和已启动工具。历史另走 `/api/sessions/[id]` 和 `/context`，不靠把所有 SSE 重放一遍。`lib/rpc-manager.ts:582–650,1005–1023`；`app/api/agent/[id]/events/route.ts:7–36`；`lib/agent-event-stream.ts:175–245`；`lib/agent-event-wire.ts:79–132`；`hooks/useAgentSession.ts:534–547,899–911,1671–1701`。

### 思考、正文、过程区

- Provider `streamSimple(model, context, options)` 收到 `TranscriptContext`；查系统提示/工具宣告用 `getCurrentSystemPrompt(context.messages)` / `getCurrentTools(context.messages)`。用标准 `AssistantMessageEventStream`：一个 `start`，更新每个 block 后发同 `contentIndex` 的 `thinking_start/delta/end` 或 `text_start/delta/end`，最后一个 `done` 或 `error` 并结束流。初始化 `stopReason: "pending"`、完整 usage 结构；请求初始化失败可直接 `error`。Agent 将事件变为 `message_start/update/end`；Web 在 `requestAnimationFrame` 批次里应用 delta。`SDK/docs/custom-provider.md:174–204`；`CORE/dist/agent-loop.js:272–341`；`lib/streaming-message.ts:55–107`；`hooks/useAgentSession.ts:1299–1320,1806–1845`。
- Thinking 是会增长的折叠行（摘要、计时，展开看全文），单行默认折叠，有浏览器偏好；长历史可只带摘要，展开后才请求 `/entries/[entryId]/thinking`。外层还有过程面板：进行中默认展开，已回答的过程通常收起，尾部无最终答案时可默认展开。`lib/thinking-expansion-preference.ts:1–16`；`components/MessageView.tsx:131–153,1224–1351`；`lib/session-reader.ts:952–966`；`components/ChatWindow.tsx:618–659,2159–2178,2346–2362`。
- 正文用 `SafeMarkdownBody` → `MarkdownBody`，去 ANSI，有 streaming fence / Markdown 分块和超长正文纯文本回退（100,000 字符阈值）。最终尾部正文与过程分开；夹在思考/工具间的短文本通常留在过程，较长的过程正文（`trim().length > 400`）会提到答案视图。不要用 text delta 冒充可原位更新的计划：text delta 是追加，非结构化状态替换。`components/MessageView.tsx:61–102,1207–1211`；`components/MarkdownBody.tsx:49–92,185–196`；`lib/message-display.ts:192–238,263–286`；`lib/streaming-message.ts:60–77`。

### 工具：可用的渲染契约，不等于 ACP 可直接发的事件

Pi 原始 `AssistantMessage.content` 的 `{type:"toolCall",id,name,arguments}` 被 Web 规范化成 `{type:"toolCall",toolCallId,toolName,input}`；`role:"toolResult"` 通过 `toolCallId` 配对，不单独出通用气泡。`toolcall_start/delta/end` 描述**生成参数**，`tool_execution_start/update/end` 是**执行阶段**，两者不可互换。`lib/normalize.ts:27–69`；`lib/streaming-message.ts:108–151`；`components/ChatWindow.tsx:1505–1525`；`components/MessageView.tsx:291–314,1177–1205`；`hooks/useAgentSession.ts:1920–1981`。

| 工具/输入（指已有正当 call/result 的展示） | 实际效果与最佳形状 |
|---|---|
| 一般工具 | 通用折叠步骤卡，不是每个名字一个独立 renderer。图标按名字，预览优先 `command`、`pattern`、`query`，其次 `path` / `file_path`，再找可读值；任意 ACP `title` 不会变成 header label。展开显示字段或 JSON、结果文本（`content: [{type:"text",text}]`）、图片；`isError` 着色，普通结果无 Markdown/xterm。`components/ToolIcon.tsx:23–76`；`lib/tool-preview.ts:14–43`；`components/MessageView.tsx:1382–1458,1503–1605,1957–1991`。 |
| `bash`、`powershell` / command-only 输入 | `{command:"…"}` 给出命令摘要、复制按钮、展开的 `$ …` 和等宽输出；有其他参数则回到参数字段视图。活跃 `partialResult.content` 仅对白名单**精确** `bash` / `powershell` / `Agent` 入 `activeToolResults`；用同一 id 的**累积输出快照**，不是裸 delta。`!` 的 `bashExecution/bash_output` 是另一条路径，不是 ACP terminal renderer。`components/MessageView.tsx:1390–1404,1458–1470,1503–1525,2262–2266,311–313`；`hooks/useAgentSession.ts:1932–1958,2016–2035`。 |

| 任何配对成功的工具的 diff | **可以**：`result.details.patch`（优先）或 `result.details.diff` 是**非空字符串**。path/oldText/newText 对象、单独塞 `content[].text`，都不会自动进 diff view。推荐带 `--- a/file`、`+++ b/file`、`@@ -1 +1 @@` 的统一 diff；`parseUnifiedPatch` → `SplitDiffFiles`（桌面双列、移动端 unified），不识别时回退至 patch 纯文本；错误结果不用 diff 分支；成功 diff 分支替换普通结果区域，不同时渲染终端输出。SDK 内置 edit 同时提供给 TUI 的 `diff` 和标准 `patch`，Web 优先后者。`SDK/dist/core/tools/edit.js:129–137`；`SDK/dist/core/tools/edit-diff.js:449–475`；`components/MessageView.tsx:1419–1427,1548–1568,1678–1691,1714–1769,1920–1931`；`lib/patch.ts:24–139`。 |
| `apply_patch` / namespaced 变体 | `{patch:<Codex V4A text>}` 走专门解析器，也可从流式 JSON 中提取部分 patch；输入 patch 存在时它优先，常规配对结果区不再画。不要把 unified diff 误传成 V4A 参数。`lib/tool-names.ts:27–38`；`components/MessageView.tsx:1408–1418,1527–1558,1656–1669,1693–1711`。 |

- **防止双执行**：正常 final `AssistantMessage` 只要含 `toolCall`，即使 `stopReason:"stop"`，Pi 也扫描并执行；未注册名字成 `Tool … not found`，不是 display-only，真实 `bash` / `edit` 则会重复执行。`length`/`error`/`aborted` 有专用收尾逻辑，不能拿它们伪装成功。Provider 流协议里没有发送 `toolResult`、`tool_execution_update` 或 ACP `tool_call_update` 的入口。当前可用方案是 Markdown（diff 可用 fenced `diff` 源码，不是 `SplitDiffFiles`）/可见 custom 摘要；真实配对卡需要宿主展示通道。`CORE/dist/agent-loop.js:147–193,281–341,353–370,478–526`；`AI/dist/types.d.ts:577–647`；`components/MarkdownBody.tsx:78–91`。

## 2. `ctx.ui`：权限窗口、无客户端与兼容限制

| API | Pi Web 行为 |
|---|---|
| `select(title,options,opts)` / `confirm(title,message,opts)` | 聊天窗格内居中、可收起为待处理条的 overlay（`role="dialog"`，不是浏览器 `alert/confirm`，也不是全局 top-layer modal）。select 是可上下键导航的 Markdown 选项，返回原字符串；confirm 说明用 Markdown，确认/取消。无响应默认分别为 `undefined` / `false`。`lib/rpc-manager.ts:2078–2097`；`components/ChatWindow.tsx:1967–1972,2731–2907`。 |
| `input` / `editor` | 同一 overlay；单行 placeholder + Enter / 多行 prefill + Ctrl/Cmd+Enter；取消/Escape 返回 `undefined`。同类请求客户端排队去重。应用自己的 routine approval 有专属 inline 卡，不是通用 `confirm` 行为。`lib/rpc-manager.ts:2098–2111`；`hooks/useAgentSession.ts:1266–1275`；`components/ChatWindow.tsx:1967–1969,2453–2463,2870–2911`。 |
| `custom()` | Headless TUI 兼容：服务器调 component 的 `render(width)`，用 `PlainTextTheme`，浏览器显示可收起的等宽文本对话层，转发终端样式键盘/文本输入；不是 DOM 或任意 React renderer。默认无普通 dialog 的 `opts.timeout` 倒计时。`lib/rpc-manager.ts:1874–2015,2162`；`components/ChatWindow.tsx:2923–3061`。 |
| `notify`、`setTitle`、编辑框 | `notify` 去 ANSI，聊天窗浮动通知（info/warning/error），普通约 5 s，长文本约 15 s，带链接可到 60 s，可暂停；`setTitle` 改浏览器 `document.title`，不是持久会话标题；`setEditorText` 和 `pasteToEditor` 分别替换/插入可编辑文本，不擦图片/引用。`getEditorText()` 固定空字符串。`lib/rpc-manager.ts:2112–2125,2153–2178`；`hooks/useAgentSession.ts:262–266,1231–1249,1276–1299,2040–2045,3110–3127`；`components/ChatWindow.tsx:1953,2647–2713`；`docs/extensions.md:33–35`。 |
| `setStatus` / `setWidget` / 其他 TUI 能力 | **`setStatus` 服务端确实发 SSE，但客户端 switch 不处理，实际没有 status bar**。`setWidget` 数组请求发出但同样无人渲染；factory 不运行。`setFooter/setHeader`、working indicator/message/visibility、hidden thinking label、terminal-input 和 autocomplete provider、editor component 是空操作；主题读取有 Web theme，不能切换；`getToolsExpanded()` 固定 false。`lib/rpc-manager.ts:2126–2184` 对照 `hooks/useAgentSession.ts:1266–1298`。 |

- 正数毫秒且 `<= 2_147_483_647` 才有服务端 deadline；默认没有，前端 `expiresAt` 倒计时由服务器 `extension_ui_closed` 真正关闭。调用传入的 `opts.signal` 取消返回默认，Stop 的会话 UI controller 取消可让等待 reject，关闭 wrapper 时也清理。**没有客户端不等于 deny**：没有“当前无浏览器就返回默认”的分支；请求留在 wrapper，订阅建立后重放，除非超时、取消或 wrapper 被回收。`ctx.hasUI` 只检查是否绑定非 no-op UI，不检测在线人数。普通通知最近 10 条 / 2 分钟可重放，不是持久收件箱。`lib/rpc-manager.ts:211–212,965–982,1005–1028,1840–1867,2017–2075,2112–2125`；`SDK/dist/core/extensions/runner.js:406–411,630–650`；`components/ChatWindow.tsx:2746–2762`。
- 可见会话 SSE 保活，打开的标签每 30 秒续 idle lease；默认 idle 10 分钟，运行中另有保活，所以别拿 idle 当权限超时。`session_start` 有待答阻塞对话时，启动和 `get_state/get_commands` 可先返回，答完再刷新完整 ready 状态，其他执行命令等待。Web 还能给阻塞请求加标签等待标记、提示音等。`AGENTS.md:58–65`；`lib/rpc-manager.ts:537–540,807–824,918–929,965–982`；`hooks/useOpenSessionLeases.ts:5–33`；`hooks/useAgentSession.ts:1153–1215,1266–1275`；`components/ChatWindow.tsx:1023–1030`；`components/AppShell.tsx:1529–1558`。
- **ACP 权限建议**：二选用 `confirm`，多选用有唯一标签的 `select`，只映射本次 ACP 声明的 option ID；设置合理 timeout、传本次请求的 signal，取消/超时/Stop/未知值绝不当作批准。命令、路径、diff 概要可写进 Markdown 说明，不必用 `custom()` 模拟复杂选择器。可在同一扩展通过 Pi 的 `provider_stream_event` hook 拿 `ctx`（provider 须调用 `options.onProviderStreamEvent`），或由会话桥传递对应 ctx；它是服务端 hook，不会自动变 Web 卡。`SDK/docs/custom-provider.md:195–204`；`SDK/dist/core/sdk.js:241–276`；`lib/rpc-manager.ts:2078–2097`。

## 3. 用户图片：从浏览器到 `streamSimple`

- 剪贴板、drop、挑选文件进 composer `processImageFiles()` / `readPromptImageFile()`；图片做附件，非图片是文件上传 + 路径引用。`@` 图片路径也只是 prompt 中路径，不等同于 inline bytes。Web 每条最多 **10 张，每张原文件或服务端 decoded bytes ≤ 10 MiB**；POST `images: [{type:"image",data:<base64>,mimeType:"image/…"}]`，不是 data URL，也不发送预览 URL。API 检查 `image/` 前缀、base64 形状、数量、字节，不是 MIME 白名单。`components/ChatWindow.tsx:1488–1499`；`components/ChatInput.tsx:985–1030,1673–1684`；`docs/ui.md:265–271`；`hooks/useAgentSession.ts:2125,2211–2216,2812–2819`；`lib/image-attachments.ts:1–59`；`lib/rpc-manager.ts:1124–1136,1195–1200`。
- 浏览器嗅探 PNG/JPEG/GIF/WebP；保留原始 bytes，达到 **4.5 MiB base64** 才尝试用 canvas 转 ≤2000 px、JPEG 0.85，前提是能解码且结果更小，否则保留原图。不要把另一套生成/改图的 >1 MiB 压缩规则当普通消息。SDK 再按 `images.autoResize` 与模型 `inputLimits.images.resize` 处理：默认 2000×2000、base64 小于 4.5 MiB；PNG/JPEG/GIF/WebP 原生，其他格式尝试转 PNG，失败省略并附文本提示；禁用自动缩放可保留较大受支持原图。排队图片在投递时同样走 SDK 归一化。`components/ChatInput.tsx:411–489`；`SDK/dist/core/agent-session.js:1569–1591,1676–1694,1888–1930`；`SDK/dist/utils/image-process.js:1–79`；`SDK/dist/utils/image-resize-core.js:8–17`；`docs/ui.md:267–268`。
- Provider 从 `context.messages` 的 `role:"user"` 找 `content: [{type:"text",text}, {type:"image",data,mimeType}, …]`（也接受纯文本用户消息）；按顺序消费，按 ACP 协商到的图像能力映射，不从历史 UI URL 读。Web 用 `model.input` 做**提示而非禁发**，未知能力不警告；Pi `images.blockImages` 可把发送给 provider 的图替换为提示文本；不要假定自定义流会自动继承内置 API serializer 的非视觉图片剔除。`AI/dist/types.d.ts:273–278,376–380`；`CORE/dist/agent-loop.js:268–280`；`components/ChatInput.tsx:644–658,1297–1309`；`SDK/dist/core/sdk.js:161–189`；`AI/dist/api/transform-messages.js:1–59`。历史显示才可能把图像转成按 entry 懒取的 URL，编辑时转回 base64。`docs/ui.md:270–276`。

## 4. Resume、Fork、Tree 与 ACP 会话身份

## 6. Steer、Follow-up 与 Stop

- Composer 的 steer/follow-up 都 POST `{type:"prompt",message,streamingBehavior:"steer"|"followUp",images?}`，不是直接打 wrapper 的 `steer` / `follow_up`（那两个 API 也存在）。让 SDK 原子决定：还在跑就排队，刚结束就开新 prompt；手动 compaction 的拒绝有 Web 暂存队列。`components/ChatInput.tsx:1493–1523`；`hooks/useAgentSession.ts:2792–2851`；`lib/rpc-manager.ts:1194–1252,1511–1521`；`SDK/dist/core/agent-session.js:1740–1773`。
- 投递条件：**steer 不 abort 正在 stream 的 provider**，在下个 turn 边界优先取得（当前响应及那一批 Pi tools 完成后；若在准备 turn 可更早取）；**follow-up** 在 agent 本来将结束、没有待处理工具/steer 时再取。`one-at-a-time` / `all` 是 SDK 队列设置。队列送达的新 `role:"user"` append 到 transcript，然后再次调用 `streamSimple`；不是同一次 ACP 请求的实时注入。ACP 工具都在一次 stream 内的话，steer 只能等这次 ACP stream 返回；要真正 mid-run steer 得另有 ACP 与宿主支持。`CORE/dist/agent-loop.js:90–125,146–206,268–280`；`CORE/dist/agent.js:58–86,172–193,304–328`；`SDK/dist/core/agent-session.js:1888–1930`。
- Stop 按钮（运行中 Esc 也可）→ `abort` 命令 → Web 收回未送达的消息/图片到草稿并取消 UI → `inner.abort()` → Pi `agent.abort()` → 当前 run 的 `AbortController` → **provider `options.signal`**。Provider 必须监听 signal，取消对应 ACP prompt 和未处理权限，不要仅停发 SSE，收尾时 `stopReason:"aborted"`；Stop 也取消 SDK retry sleep。关闭 browser SSE **不等于** Stop。`components/ChatInput.tsx:1650–1654,2030–2059`；`hooks/useAgentSession.ts:2389–2453`；`lib/rpc-manager.ts:1267–1288`；`SDK/dist/core/agent-session.js:2082–2102`；`CORE/dist/agent.js:216–223,345–364`；`CORE/dist/agent-loop.js:275–280`；`docs/extensions.md:37–41`。

## 8. 用量、错误、重试与宿主限制

- 原生 composer footer 有模型、effort、工具、context ring、缓存命中、会话费用、耗时指标；不是扩展可替换的 footer。使用 `AssistantMessage.usage` 的 input/output/cacheRead/cacheWrite/totalTokens 和 cost breakdown/total（美元）记录真实计量，最终消息填准确值，不拿 ACP terminal bytes 猜 token。若没有 ACP 用量，保留零值并承认未知；Usage 可依价格配置估计部分成本，0 不保证免费。会话 stats 汇总整文件，包括 compaction/branch-summary/cache-warm usage；可有独立完成提醒/音效，不等于 `ctx.ui.notify`。`AI/dist/types.d.ts:292–320,382–406`；`lib/session-stats.ts:38–66,119–142`；`components/ChatInput.tsx:1882–1914,2824–2832`；`app/api/usage/route.ts:19–55`；`components/UsageStats.tsx:250–284,385–402,477–480`；`components/ChatWindow.tsx:823–831`；`components/AppShell.tsx:1455–1471`。
